# Gemini tool-calling agent

Feature 9 adds a working text entry point in **Ask Iris**. Select a history source and timezone, enter a question, then send it. Gemini chooses allowlisted tools, including dependent calls across multiple model turns, and selects the supporting facts for the answer. Each sentence links to a compact evidence card. Live, mock and demo-seed records remain separate. Asking never starts capture or saving. Cancel, changing the source/timezone, navigating away, reloading or deleting history discards the current answer/request.

## Setup

Set `GEMINI_API_KEY` in the ignored root `.env`; leave `.env.example` credentials empty. The API backend owns the key. `GEMINI_MODEL` defaults to `gemini-3.8-flash` and accepts a Gemini model ID. `TRUEIRIS_REASONING_PROVIDER=gemini` is the default; `mock` explicitly selects a deterministic test provider that queries the same tools and never inserts history. A failed Gemini request never falls back to mock. The answer visibly labels the reasoning provider and selected data source separately.

The API also needs its existing private token, server-owned identity and database configuration. Start with `pnpm dev`. Settings reports configuration availability; a configured key is not a successful provider health probe. Actual authentication, model access and quota are tested when a question is sent. Missing configuration, unauthorized API access, provider failures, unavailable storage, busy admission, cancellation and incomplete evidence have explicit states. Existing text/history access remains usable when voice is unavailable.

The production adapter uses Google's [Generate Content API](https://ai.google.dev/api/generate-content) with function declarations, header authentication, forced function selection, a fixed HTTPS host and refused redirects. The default model is listed in the [Gemini model catalog](https://ai.google.dev/gemini-api/docs/models). Full model content, including opaque thought signatures, is preserved between tool turns solely in backend request memory; it is never returned to the UI. Request storage is disabled with `store: false`; this does not override the provider's applicable service terms or retention policies.

## Tools and evidence

| Tool                    | Behavior                                                                                                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_current_state`     | Projects current main-owned local state and fresh, accepted, matching-source metrics. Reports that the state is client supplied.                                                                          |
| `get_metrics`           | Exact quality-filtered period statistics and lowest-value epoch location when all detail is available; first/last accepted epoch means do not imply continuous coverage.                                  |
| `get_context`           | Recorded manual labels, clipped foreground application/activity/idle duration; missing and ambiguous intervals remain unknown.                                                                            |
| `compare_baseline`      | Earlier per-metric personal activity or local time-of-day references, including sample/date support and inadequate-history states.                                                                        |
| `get_daily_summary`     | Timezone-aware calendar date statistics/context, including 23/25-hour days and a current-day cutoff at request time.                                                                                      |
| `find_similar_sessions` | At most five recent activity-matched sensing periods in an earlier bounded range, with accepted metric means. Matching uses recorded manual labels and recency, not semantic or physiological similarity. |
| `search_memories`       | Explicitly unavailable until Feature 11 creates semantic episodic memory. No recalled episodes are fabricated.                                                                                            |
| `respond`               | Chooses ordered fact IDs already returned by tools. It cannot introduce prose, numeric claims or citations that were never retrieved.                                                                     |

Zod validates every input and output. Source, timezone and owner are bound outside model arguments. Metric/context periods are positive and at most 26 hours; historical searches are at most 30 elapsed days with limits 1–5. Future ranges and invalid dates are rejected. The SQL for history is parameterized, owner/source scoped and read only. No model SQL, generic database access, scraping, capture controls, export or deletion tool is exposed.

Each tool returns bounded, server-generated descriptive facts with stable request-local IDs, numeric values where applicable, UTC source periods and ready/empty/limited/unavailable states. Tool statistics inherit existing quality/confidence/talking gates; absence never becomes zero. Window titles and classification reasons are excluded from evidence even if captured and saved locally. Application names are quoted as data and never used as instructions.

Gemini controls retrieval and fact selection; the server assembles final sentences from verified fact templates. This intentionally favors traceable numerical statements over unrestricted stylistic prose. Unknown final citations fail closed to a clearly incomplete answer containing only retrieved facts. Missing/limited evidence cannot be omitted by the model. Neither templates nor the tool contract introduce diagnoses, physiological stress/focus scores, causal conclusions, or claims that activity-matched sessions are semantic matches. The final response contract validates unique evidence IDs, exact selected facts, source/range scope and the correspondence between answer text and citations.

## Limits and privacy

One active question per configured API owner/process is admitted. Each request has at most eight model turns, twelve retrieval calls and four functions per turn. The backend deadline is 60 seconds, each provider call 20 seconds, and desktop transport 65 seconds. Cancellation interrupts even a stalled provider promise; already-running SQL remains subject to its existing statement timeout. Provider and desktop response bodies are capped at 256 KiB, each evidence result at 16,000 characters, and conversation content at 128,000 characters. There is no hidden unlimited retry loop.

The question, source/timezone/request time and only requested projected evidence are sent to Gemini after the user's Send action and visible disclosure. The database is never sent wholesale. Camera frames, screenshots, window titles, credentials and owner IDs are not sent to the model. Current state is added by desktop main, never by the renderer. Questions, answers, tool transcripts and thought signatures are neither logged nor stored by TrueIris; they live only in request/view memory. Existing saved-history deletion removes retrieval inputs and cancels an active agent request. Native workers and renderer receive no Gemini credentials.

Authenticated `POST /agent/ask` accepts a strict question/source/timezone plus a validated projection of current local state. The API binds tools to its token's configured identity and inherits the existing quota/body limit. Named `askIris`/`cancelIris` IPC capabilities connect renderer and main. Private transport rejects mismatched request/source responses and inconsistent evidence. The initial text surface is provided for validating Feature 9; richer conversation remains a later feature, while Feature 12 adds the [ElevenLabs voice loop](ELEVENLABS_VOICE.md), and Feature 10 adds the [dedicated last-30-minute explanation and timeline highlight](RECENT_EXPLANATION.md).

## Verification

`pnpm check` covers formatting, lint, type checks, unit tests and production builds. Agent tests cover dependent retrieval, model signatures, arbitrary SQL/unknown argument rejection, unsupported citations, failures/partial evidence, iteration bounds, cancellation/admission, freshness/source filtering, memory uncertainty and DST. API/main tests cover authentication, request validation, owner scope, private transport and answer provenance. Built desktop tests drive Ask Iris, source changes, evidence citations, cancellation, empty history, navigation cleanup and configuration failure.

`pnpm test:database` verifies real activity-matched session queries, quality-gated means, owner/source separation, result limits and fractional period clipping using random fixture owners. `pnpm test:gemini` explicitly calls the real configured Gemini model against synthetic in-memory fixtures; it sends no private history, prints only status/turn/tool metadata, and checks both a completed cited multi-tool answer and the dedicated eight-retrieval recent explanation. No external provider is called during ordinary unit/desktop tests.
