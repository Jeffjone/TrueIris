# Event reconstruction

Feature 16 adds **What happened here?** beneath a selected Timeline point or range. Select the saved history source and display timezone, click or inspect a period, then ask for its reconstruction. The recorded sequence shows timestamps; Gemini chooses a concise chronological narrative from the verified event facts, with links to their evidence.

The named `reconstructEvents` bridge fixes the question and passes only the selected range/timezone. Main projects current state and owns authentication. The existing agent route, single-request admission, cancellation and provider adapter are reused. `reconstruct_events` is an allowlisted tool; the selection is pinned, source/owner scope cannot change, and the agent must retrieve these events before responding. Unsupported citations or prose cannot enter the answer. The response carries the exact selected range; ordinary text, recent explanations and voice retain their existing behavior.

Events come from saved foreground applications, manual activity labels, desktop idle transitions, continuous-interval switch-counter increments, accepted pulse epochs, supported earlier personal baselines and signal gaps. A first foreground observation is not an app opening time. An activity label does not reveal task contents, such as authentication work. Window titles, classification reasons, raw media, intentions and causal interpretations are excluded from Gemini. Overlapping desktop sessions suppress ambiguous app ordering. Pulse comparisons do not bridge session boundaries or long recording gaps; baseline comparisons use only matching activity or local daypart and earlier history.

At most 18 chronological event facts plus mandatory uncertainty statements enter one reconstruction. Limited, missing or unavailable evidence stays explicit; select a shorter period for omitted detail. Source, timezone, selection, refresh and navigation changes discard the view; Cancel reconstruction stops orchestration. No sensing, saving or voice starts, and no reconstruction cache is written. Existing provider retention policies apply to the explicit question/evidence transport.

Validation: `pnpm check`, `pnpm test:integration`, and the opt-in `pnpm test:gemini` synthetic reconstruction scenario. Tests cover exact selection/owner scope, missing data, overlapping sessions, gaps, privacy projection, premature answers, source/future-range rejection, cancellation and the built desktop flow.
